# Blank disk templates

These synthetic D88 files are generated by the pinned Bubilator88Core's
`D88Disk.createFormatted(type:name:initBasicFAT:)` and `serialize()` methods.
They contain no BIOS or game data. The disk name is empty; the Windows shell
sets it from the destination filename when creating a disk.

Each media type (2D, 2DD, 2HD) has an erased image and an N88-BASIC-initialized
image. The formatter owns the geometry, sector data and FAT contents; the shell
does not implement those rules again. Gzip keeps the six embedded templates
small without adding a C ABI function or changing the core revision.

Regenerate from the repository root with Swift installed and the sibling core
clone available (`BUBILATOR88_CORE_DIR` overrides its location):

```sh
python scripts/make_blank_disk_templates.py
python scripts/make_blank_disk_templates.py --check
```

The script reads the formatter at the exact `Package.resolved` revision with
`git show`, compiles it with `scripts/blank_disk_templates.swift` in a temporary
directory and compresses the six results. It does not modify the core clone.
`manifest.json` records the revision, sizes and SHA-256 hashes of uncompressed
images. Windows tests verify byte identity and that this revision matches the
app's pin. Regenerate these assets when updating the core pin, and commit the
manifest and any changed templates together.

Windows CI also runs `--check` against the checked-out pinned core, including
when only templates or generator scripts change. Hash tests alone cannot prove
that a template and its manifest were actually produced by the core formatter.
